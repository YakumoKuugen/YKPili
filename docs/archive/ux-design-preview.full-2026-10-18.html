01设计定位与取舍

YKPili 是 B 站第三方桌面客户端，材质基线移植自 BewlyCat。本规范在既有 Token 层之上补齐 信息架构与卡片信息层——现有首页只有「封面 + 标题」，缺少顶栏、分类导航与 UP 主信息， 这正是与参考界面差距最大的地方。

与 UX 插件建议的偏离说明

插件按"视频流媒体"检索给出的是 Cinema Dark 方案（背景 #0F0F23、 强调色 #E11D48 影院红、纯黑底）。本项目不采纳这三项，理由如下——属于刻意例外，非遗漏：

不采用纯黑背景：插件自身反模式清单即写明「avoid pure #000000 (OLED smear)」。 项目用 #222428（bew-dark-base 与黑混合 20%），滚动时无 OLED 拖影。
不采用影院红强调色：品牌已锁定 B 站蓝。第三方客户端换掉品牌色会削弱识别度， 且 #E11D48 与错误态红 #E5484D 在深色下难以区分，破坏状态语义。
采纳：暗色优先的层次模型、玻璃拟态表面、圆角 12/16 卡片、 cubic-bezier(0.16,1,0.3,1) 类缓动（项目已有同源 EaseStandard）、 点击播放（禁自动播放）。

核心约束（全部来自实际代码，不是推测）

2026-10 技术选型变更：以下两条约束已失效。新底座 GPUI Metal renderer 把视频帧 （CVPixelBuffer）与控件合成在同一条渲染管线，控件可以压在画面上、也可以做位移与透明过渡。 第 06 节最终定为：播放窗口不动，右侧 hover 热区唤出浮层面板。 本节保留原文仅作历史说明。
① 没有 backdrop-filter。Avalonia 12 的 Visual.Effect 只有 DropShadowDirectionEffect，没有 BlurEffect，也没有自定义 Effect 扩展点。 BewlyCat 的 blur(20px) saturate(180%) 无法移植。 请用顶部开关切换「Avalonia 实际 / 设计理想」直观对比差距。
② 原生视频视图既不可被覆盖，也不跟随渲染变换 2026-10 已失效 旧底座下它无法被 Avalonia 内容盖住（控制栏只能占独立高度）、也不跟随 RenderTransform。 新底座 GPUI Metal renderer 把视频帧与控件合成在同一条管线，这两条均不再成立， 第 06 节最终定为「播放窗口不动 + 右侧 hover 热区唤出浮层面板」。

补偿策略（四层叠加，前 3 层已可精确复刻）：

  • ① 半透明填充 SurfaceElevated；叠加在高频内容之上时改用 SurfaceElevatedStrong（0.92）
  • ② 1px 半透明亮边 BorderPopover
  • ③ inset 白色高光 EdgeGlow1/2 —— 玻璃质感的主要来源，与 BewlyCat 同源
  • ④ 外阴影 Shadow1–4 定层级
落地红线：任何浮在视频网格之上的面板（顶栏、吸顶分类、Dock、播放器） 必须用 on-content / Strong 变体，否则背后封面会直接干扰文字阅读—— 没有模糊可以依赖。预览中顶栏已按此处理。

场景层级令牌（z-index）

原文把 20/25/30/40 散落在第 06、08 节的正文里，没有令牌化。 这里补成一张表：先场景、后层内——播放浮窗作为整体场景压过整个首页， 场景内部的层号不参与跨场景比较。

03首页实景预览

这是目标态：在既有封面网格之上补齐三层缺失结构 —— 固定顶栏（搜索）、吸顶分类导航、 左侧浮动 Dock，以及卡片的信息层（播放量 / 弹幕数 / 时长 / UP 主）。 把鼠标移到卡片上可看悬停反馈，滚动可看吸顶与玻璃表现。

YKPili — 3840 × 2160 · 18 列自适应
YKPili

顶栏 · 64px

高度 TopBarHeight 64，主控件 46（TopBarControlHeight）。 搜索框居中、最大宽 520、胶囊圆角。右侧图标组 38px 圆形热区，含未读红点。 压在网格之上，故用 SurfaceElevatedStrong。窗口内边距 20px。

分类导航 · 吸顶

玻璃胶囊容器内 5 个 tab，选中态用主题色实底 + 主题色投影。 吸顶时顶栏下方 Space4 间距，内容区因此需要 padding-top = 顶栏 + tabs，否则首行卡片被遮挡（design_review 判为「中」）。

左侧 Dock

垂直居中浮动，42px 圆形玻璃按钮。不做底部 Tab 栏—— 桌面端底部导航不符合平台习惯，且 design_review 明确要求主导航项 ≤ 5， Dock 恰好 5 项，其余入口收进头像菜单。

04封面卡片解剖

卡片是首页唯一的重复单元，也是当前实现与参考界面差距最大的组件。 现状只有封面 + 两行标题；目标态需要补齐信息层，同时保持 208×166 的单元格几何不变 —— 虚拟列表的 CellWidth/CellHeight 计算依赖它，改动会连带影响容器池推导。

卡片状态实测

从左到右：默认态 → 悬停态（放大 1.03 + 阴影抬升 + 操作浮出 + 封面缓推 1.04） → 直播中（粉色角标）→ 已观看（进度条）→ 骨架加载态。 悬停不是唯一手段：点击、键盘聚焦都会触发同一套视觉，触摸设备不依赖 hover。

06播放浮窗与可收起面板

点击卡片后弹出的是大浮窗而非居中模态：播放窗口本身不动—— 视频区铺满整个浮窗，控制栏悬浮在画面下沿，右侧浮层面板承载全部视频信息。 面板的唤出靠它自己：鼠标进入面板区域即展开为 400px，移出即收回为 200px。 把鼠标移到浮窗右侧那条面板上试试（或点下面的按钮）。

叠层合成已打通（2026-10 技术选型）：视频帧（CVPixelBuffer）与 UI 控件在 同一条 GPUI 渲染管线里合成，因此控件可以压在画面上、也可以做位移与透明过渡。 旧的「控制栏必须让出独立高度」「面板只能走宽度变化」两条约束整体失效，已从本节移除。

硬约束变更记录

① 已失效：控制栏不能叠在画面上。旧底座是 Avalonia + NativeControlHost 原生视图，视频层与 UI 层分属两个渲染管线、无法互相覆盖。新底座 GPUI Metal renderer 把 CVPixelBuffer 视频帧与控件合成在同一条管线， 控制栏改为悬浮，画面高度不再被切掉 50px。
② 已失效：浮层只能走布局、不能走 transform。旧约束要求面板宽度变化而非位移； 叠层合成后浮层走 opacity / translate 即可， 既不影响视频尺寸，也不触发每帧重布局。
③ 新约束：压在画面上的文字必须有渐变遮罩。这是叠层方案唯一新增的红线。 画面明暗不可控，控制栏与进度条的对比度不能依赖画面本身， 必须在底部铺 linear-gradient 由 black 0.82 过渡到透明； 面板若是半透明，同样需要暗化底衬。

必查项

  • 收起后仍有唤回入口：面板左上角那枚按钮在收起态切换为「展开」图标，永远可达
  • 播放浮窗默认收起信息面板（沉浸优先，视频占满整宽）；点击播放只在未收起时才收起
  • 面板收起时，已选中的 Tab 与滚动位置要记住，唤回后不重置
  • 评论区要有加载骨架、空态引导、失败重试
  • 「失去焦点即收起」加 150–300ms 延迟，避免鼠标划过就闪收
  • 面板并排后视频区变窄，需验证 4K/1080p/最小窗口三档下视频比例与黑边表现
  • 窄窗口下面板是否该收窄或自动收起（窄窗口 400px 面板会挤压视频）
  • 键盘：Tab 进入面板时不得自动收起，焦点移出才收

叠层合成后必须补的验证

  • 控制栏文字压在亮画面上的对比度实测（遮罩是唯一保障，亮/暗两种素材各测一次）
  • 面板展开时横向遮住约 44% 画面——字幕/关键内容是否落在被遮区域需要抽查
  • 面板宽度 400→0 过渡期间，视频区重排是否抖动（原生视频层只有布局变化时才重绘）
  • 视频帧与 UI 合成后的色彩：NV12 视频与 sRGB 控件叠加是否串色或发灰

07登录与扫码

未登录态是独立页面：垂直居中的玻璃卡片，宽 380、内边距 32×36、ModalRadius 24。 二维码区域保持纯白不跟随主题——对比度不足会直接导致扫码失败。

扫码三态

  • 等待扫码：二维码 + 倒计时提示 + 取消
  • 已扫码待确认：二维码蒙上主题色遮罩，显示"请在手机上确认"
  • 已失效：遮罩显示"二维码已失效" + 点击刷新

约束

  • 二维码底色锁定 #FFFFFF，不跟随暗色主题
  • 轮询失败需退避重试，不要把错误直接抛给用户
  • 登录成功后卡片不闪退，直接切换为首页（保留渐变背景连续性）

无障碍

  • 二维码需提供 alt 文本："用于登录的二维码"
  • 状态文案用 aria-live="polite" 播报阶段变化
  • 取消按钮是键盘可达的普通按钮，非仅图标

09交互与动效

动效只做三件事：确认操作、表达层级、衔接状态。不做装饰性编排。

交互反馈时长 / 曲线注意
卡片悬停缩放 1.03 + 阴影抬升 + 操作按钮浮出 + 封面缓推 1.04 150ms / EaseStandard缩放不参与布局，不影响 Canvas 定位
卡片按压缩回 1.0，不改变布局边界 150ms / EaseEmphasized按压态不得引起相邻卡片位移
分类切换选中 pill 主题色实底 + 阴影；内容区保留滚动位置或回到顶部 200ms / EaseStandard切换需保留各 tab 的滚动位置（design_review 判「中」）
主题切换表面/文字色过渡，卡片需重建控件 200ms / EaseStandard卡片是代码后台按当时 token 创建，不重建会停留在旧主题
滚动加载底部骨架行渐显 300ms / EaseStandard滚动事件按行号变化节流，避免每帧重排
浮窗入场从下方滑入到顶栏下方 300ms / EaseEmphasized叠层后可走 translate；视频区尺寸不参与动画

搜索建议输入防抖 250ms 后展开建议面板 200ms / EaseStandard禁止每次按键都发请求（design_review 判「中」）

必须避免

  • 只用 hover 承载关键操作——触摸设备上不可达
  • transition: all 全属性动画，会带动布局抖动
  • 滚动中触发重布局（每帧遍历上百个容器必然掉帧）
  • 悬停时改变元素尺寸或外边距，导致网格重排
  • 自动播放视频（消耗流量与电量，插件与规范都列为反模式）

键盘与焦点

  • 网格内 ↑↓←→ 按行列移动焦点，Enter 播放
  • 焦点环用 0 0 0 3px ThemePrimary20，两种主题下都可见
  • 浮层打开时焦点陷阱在浮层内，关闭后归还触发元素
  • 滚动容器可聚焦，支持 PageUp/PageDown/Home/End

10无障碍与性能

design_review 的通用检查清单里，这两项占了近一半条目。

无障碍

  • 无 emoji 结构图标——本页全部图标为内联 SVG sprite，同一线性风格、统一 1.6 描边
  • 图标尺寸走令牌（icon-sm/md/lg = 16/20/24），不用任意值
  • 暗色正文对比度 ≥ 4.5:1、次要文字 ≥ 3:1，两套主题独立测试而非推断
  • 信息不靠颜色单独传达：直播角标同时有文字、进度条同时有数值
  • 支持 prefers-reduced-motion：关闭脉冲、缩放与入场位移
  • 尊重系统动态字体，卡片标题放大后仍保持 2 行截断不溢出
  • 图标按钮必须有 accessibilityLabel（"稍后再看"而非"按钮"）
  • 鼠标可点元素 cursor: pointer；焦点顺序与视觉顺序一致

性能（项目已有基础）

  • 虚拟列表 + 容器池：仅 (可见行+2)×列数 个控件，200 条数据不全量渲染
  • 图片懒加载 + 并发限流：SemaphoreSlim(4)，仅加载可视区域封面
  • 按行节流：滚动未跨行时跳过重排——全屏上百容器时这是流畅度关键
  • 解码尺寸受限：CoverDecodeWidth 384（2× 屏），不按原图解码
  • 图片内存缓存需设上限，长滚动后应淘汰远端的封面位图
  • 搜索输入防抖 250ms，避免瀑布式请求

落地顺序建议

  1. 先扩数据模型：CoverItem 增加 ViewCount / DanmakuCount / Duration / UpName / UpAvatar / Progress。这是所有信息层的前提，且不影响现有虚拟列表。
  2. 再补卡片信息层：同步调整 CellHeight（+ 署名行高度），验证 resize 推导仍正确。
  3. 然后加顶栏与分类：新控件统一引用 on-content / Strong 变体，避免压在网格上时文字糊。
  4. 再改造播放浮窗：保持视频铺满，新增右侧 400px 浮层面板与 hover 热区；控制栏悬浮在画面下沿并自动隐藏。 旧底座下「宽度动画导致原生视图每帧重布局」的风险已随叠层合成消失， 但仍要验证两点：浮层进出时视频不黑帧、控制栏文字在亮画面上可读。
  5. 最后补状态：骨架 → 空 → 错误 → 离线，四态共用一套 state 样式类。
  6. Dock 放最后：它依赖多页面存在，页面未就绪时先留位不放功能。

落地时必须核对

  • 新增颜色只能来自 Palette/Surfaces，禁止在视图里写 hex
  • 新增尺寸走 Dimensions，间距保持 4px 网格
  • 随主题变化的资源：XAML 用 DynamicResource；代码后台用 TryFindResource(key, ActualThemeVariant, out var v)——漏传变体会静默回退
  • XML 注释里不能出现连续两个连字符，引用 CSS 变量名时写 bew-xxx
  • 改动后跑一遍 docs/skin-preview 的亮暗截图，两套主题都要看
