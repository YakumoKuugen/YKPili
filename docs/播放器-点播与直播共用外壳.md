# 播放器：点播 / 直播共用外壳 · 结构设计

> 状态：**结构设计稿（2026-11-18）**；**2026-11-18 起增量落地**：
> 已引入 `view/mode.rs` 插槽（`ModeKind` / `ControlBarModel` / `PanelSpec` /
> `BadgeSpec`）与 `view/live/{state,actions,panel}.rs`；控制栏、面板、角标、
> 断流浮层已改为读插槽，shell 不出现 `bvid` / `room_id`。直播面板已接
> WebSocket 聊天（`yk-infra::live_chat`）与 `getInfoByRoom` 房间信息。
> **`PlayerChrome` 与 `VideoState` 的整体搬家尚未完成**（点播字段仍平铺在
> `PlayerView`），按第 2 / 3 步继续迁移即可，shell 侧接口不会再变。
>
> 要回答的问题：普通播放器与直播播放器功能高度相似，能否抽成一个壳、
> 往里塞不同组件？——**能**。壳 = 窗口 chrome，组件 = 控制栏 / 侧边面板 /
> 覆盖层；差异收敛成「数据插槽」，不把 `is_live` 铺进共享代码。

---

## 0. 结论摘要

```text
PlayerView（唯一实体，负责持有与分发）
├── PlayerChrome   入场退出 / 全屏 / 控件显隐 / 面板收放 / 指针与焦点 / 弹幕输入框
├── ModeState      点播 VideoState | 直播 LiveState（纯数据）
├── PlayerModel    播放状态（playing / volume / rate / position / duration / error）
├── widgets        控制栏、面板容器、中央播放键、Toast（只吃纯数据 + 动作回调）
└── mode/*.rs      impl PlayerView 的点播 / 直播具体动作，按 ModeState 分发
```

三条硬规则：

1. **外壳不知道业务**：`shell.rs` 里不出现 `bvid` / `room_id` / `cid` / 续播 / 历史。
2. **模式之间不互相依赖**：`view/video/*` 与 `view/live/*` 不互相引用，只共同依赖
   `view/mode.rs` 定义的插槽类型。
3. **差异用「空槽」表达**：`timeline: Option<_>`、`speed: bool`、`PanelBody` 枚举，
   而不是 `if is_live`。

## 1. 设计目标与硬约束

### 1.1 目标

| # | 目标 | 判定 |
| --- | --- | --- |
| S1 | 直播播放器复用点播的外壳与组件 | 新增直播只写 session + 插槽内容，不改 shell |
| S2 | 点播行为零回归 | `yk-player` 单测 + `player_*` / `comments_visual` / `danmaku_visual` 用例与截图逐项一致 |
| S3 | `render` 可读 | `view/shell.rs` 的主渲染函数 ≤ ~150 行 |
| S4 | 差异可枚举 | 每个共享组件能列出「点播填什么 / 直播填什么」 |
| S5 | 可增量落地 | 每一步都能编译、能回归、能回滚 |

### 1.2 硬约束（来自现有代码与 GPUI）

| 约束 | 出处 | 对结构的影响 |
| --- | --- | --- |
| `PlayerView` 全进程**只能一个实例** | `lib.rs` `LIVE_PLAYERS` 断言；`InputState` 挂在实例上 | 不能用「一个点播一个直播两个实体」；模式只能是内部状态 |
| 所有动作都要 `&mut Context<PlayerView>` | GPUI 事件回调 | 模式层不适合 `dyn Trait`；用数据枚举 + `impl PlayerView` 分模块 |
| 弹幕输入框只有一个 `InputState` | `render` 首次创建，输入内容不能丢 | 输入框状态归 Chrome，点播 / 直播共用；发送目标由模式决定 |
| 视频帧 worker 只能有一个 | `ensure_worker` / `tried_worker` | worker 归 `PlayerView`，模式只提供 URL / 音频 / Referer / 起播秒 |
| 面板 400↔200、内层固定 400 | 06 节 / `panel_width()` | 面板容器归 shell；Tab 内容归模式 |
| 控制栏宽度 = 视频区实际宽度（按收起态 200 预留） | `video_bar_geometry()` | 控制栏几何归 shell；内容归模式 |
| 全屏时没有侧边面板 | `render` 的 `(!fullscreen).then(...)` | 这是 shell 规则，不对模式开放 |

### 2.1 渲染已经天然分层

| ③ 侧边面板 | `info_panel()` / `panel_tabs()` / `tab_content()` | shell 容器 + 模式内容 |
| ④ 骑边界按钮 | `panel_toggle()` | shell |
| ⑤ Toast | `interaction_toast()` | shell 容器 + 模式文案 |

### 2.2 `PlayerView` 字段按归属分类

| 归属 | 字段（现有名字） | 说明 |
| --- | --- | --- |

| **点播会话** | `source`、`loading_source`、`load_generation`、`history_report`、`resume*`（4 个）、`link_start_secs`、`start_position`、`quality_switching`、`quality_generation`、`page_switching`、`page_generation`、`danmaku*`（12 个）、`lanes`、`scroll_lanes`、`play_time`、`tags`、`comments`、`comment_section`、`meta_generation`、`danmaku_visible`、`followed` / `follow_known` / `follow_busy` / `follow_generation` / `owner_fans`、`interaction` / `interaction_busy` / `interaction_generation`、`coin_*`、`fav_*`、`share_panel_open`、`action_row_bounds`、`overlay_closing_kind` / `overlay_generation`、`scrubbing` / `progress_track_bounds` / `last_scrub_seek` / `seek_settle_until`、`tab` | 只服务点播 |

> 这张表就是迁移清单：Chrome 那列搬进 `chrome.rs`，点播那列搬进 `video/state.rs`。
> 共享两列留在 `PlayerView`。

### 2.3 两模式差异矩阵

| 维度 | 点播 | 直播 | 共用方式 |
| --- | --- | --- | --- |
| 打开入口 | `open_bvid*` / `open_link_at_page` | `open_live(room)` | 各自实现；都写 `ModeState` |
| 取流 | `view` + `playurl`（WBI） | `getRoomPlayInfo` | 分开；worker 只吃 URL |
| 音频 | 独立音轨 `audio-add` | 单流自带 | worker 参数 `Option<audio>` |
| Referer | `www.bilibili.com` | `live.bilibili.com` | 模式提供字符串 |
| 时长 / 进度 | 有，可 seek | 无，不可 seek | `ControlBarModel.timeline: Option<_>` |
| 倍速 | 有 | 无 | `ControlBarModel.speed: bool` |
| 画质 | `accept_quality` | `g_qn_desc` | `QualityMenu` 数据统一 |
| 画面弹幕 | cid XML 自绘 | 不画 | 点播插槽 `danmaku_layer` |
| 弹幕输入 | 发送到视频 | 发送到直播间 | Chrome 输入框，模式提供 `send` |
| 面板 Tab | 评论 / 弹幕 / 选集 | 弹幕 / 直播信息 | `PanelSpec` + `PanelBody` |
| 互动 / 评论 / 续播 / 历史 | 有 | 无 | 点播 session 内部 |
| 结束 | 按设置自动关窗 | 断流浮层 + 重连 | `FinishAction` 分派 |
| 错误文案 | 取流失败 / 版权 | 下播 / 权限 / 断流 | 模式提供文案 |

### 2.4 现在的耦合点（为什么不能继续加 `is_live`）

- `render` 一个函数 450 行，十多个 `self.xxx` 分支；再加直播会逼近不可维护。
- `controller.rs` 3600 行，点播动作（评论 / 互动 / 收藏 / 分享 / 历史）与
  chrome 动作（面板 / 全屏 / 控件）混在一起。
- `PlayerView` 字段约 100 个；直播弹幕、断流、重连至少再加 10 个。
- 若共享代码里出现 `is_live`，以后加第三种播放形态（番剧 / 回放 / 短视频）
  会要求改所有 `is_live` 点。

### 4.7 共享播放状态 `PlayerModel`

保持现状：`playing / volume / muted / rate / fullscreen / position / duration /
controls_visible / controls_timer_* / error`。它是唯一被两模式共同写的状态。

## 5. 渲染管线

### 5.1 `view/shell.rs` 主流程（目标形态）

```rust
fn render(&mut self, window, cx) -> impl IntoElement {
    self.sync_window_state(window, cx);      // 全屏 / 焦点 / 可见性 / 指针 watchdog
    self.ensure_worker(cx);                  // 共享：按 mode 提供的 source 起 mpv
    self.ensure_playback_loop(cx);           // 共享

    let slots = self.build_slots();          // mode → ControlBarModel / PanelSpec / Overlay
    let content = div()
        .id("player-content")
        .absolute().inset_0().bg(rgb(0x0B0F14))
        .child(self.video_surface(window))                 // ① 共享布局
        .children(self.mode_danmaku_layer(window))         // ①b 仅点播返回 Some
        .child(self.status_line())                         // ①c 共享容器
        .child(self.center_play(cx))                       // ①e 共享
        .children(self.badge(slots.badge))                 // ② 共享容器
        .children(self.control_bar_area(&slots.control, window, cx))
        .children(self.panel_area(&slots.panel, window, cx)) // ③ 共享容器 + 模式内容
        .children(self.panel_toggle(cx))                    // ④ 共享
        .children(self.overlay(slots.overlay, cx))          // ⑤ 模式内容 + 共享壳
        .children(self.toast(cx))                           // ⑥ 共享
        .on_mouse_move(...)                                 // 共享
        .on_hover(...);
    // backdrop / scrim / entrance / closing 动画：与现在一致
    div().child(backdrop).child(scrim).child(content)...
}
```

### 5.2 几何契约（shell 独占）

| 量 | 规则 | 现有函数 |
| --- | --- | --- |
| 视频区 | 窗口四周 16，右侧扣 `INFO_PANEL_COLLAPSED`（200）；全屏无扣减 | `playback_width` / `video_bar_geometry` |
| 控制栏 | 宽度 = 视频区实际宽度；不随面板展开变化；面板 400 可盖住右端 | `video_bar_geometry` |
| 面板 | 400 / 200，内层按 400 排版；全屏不挂 | `panel_width` / `info_panel` |
| 弹幕区 | 点播：`playback_layer_width(window, panel_width())`，面板展开时弹幕区变窄 | 保持现状，不在本次改变 |
| 入场 / 退出 | 280 / 260ms，`ease_entrance` | 现状 |

> 几何规则只允许 shell 改。模式不允许直接设置 `left/right/width` 去绕开契约。

## 7. 生命周期

### 7.1 打开点播

```text
PlayerView::open_bvid_at_page(bvid, page, seed, cx)
  ├─ chrome.cancel_closing();
  ├─ chrome.reset_panel_for_new_source();       // 面板收起、Tab 归 0
  ├─ worker = None; tried_worker = false; ...    // 共享运行时复位
  ├─ mode = ModeState::Video(VideoState::begin(bvid, page, seed));
  ├─ spawn: fetch_playback → 代际校验
  └─ 成功：video.source = Some(src); start_position = resolve_resume(...);
           begin_history_report(...); ensure_worker(); spawn danmaku/meta/interaction
```

### 7.2 打开直播

```text
PlayerView::open_live(room, cx)
  ├─ chrome.cancel_closing();
  ├─ chrome.reset_panel_for_new_source();       // 面板收起，Tab 默认「弹幕」
  ├─ worker = None; ...
  ├─ mode = ModeState::Live(LiveState::begin(room));
  ├─ spawn: fetch_live_playback → 代际校验
  └─ 成功：live.source = Some(src); ensure_worker(); live.chat.connect()
```

### 7.3 关闭 / 切源 / 析构

| 时机 | 点播要做 | 直播要做 |
| --- | --- | --- |
| 切到另一个视频 / 直播 | flush 历史、保存续播、递增代际 | 断开弹幕、递增代际 |
| 开始关闭动画 | 同上 | 断开弹幕 |
| `Drop` | 兜底 flush 历史 + 保存续播 | 断开连接（Drop 内） |
| 结束 | `FinishAction::ClosePlayer` 或 `StayOnLastFrame` | `ShowReconnect`（不自动关） |

`PlayerView::Drop` 保持现状，但把「点播专属」逻辑收进 `VideoState::on_drop()`；
直播的 `LiveState::on_drop()` 负责停止 WebSocket 线程。

### 7.4 结束策略

```rust
match &mut self.mode {
    ModeState::Video(v) => match v.on_finish() {
        FinishAction::ClosePlayer => self.begin_close(cx),
        FinishAction::StayOnLastFrame => { /* 暂停 + 常显控制栏 */ }
        _ => unreachable!(),
    },
    ModeState::Live(l) => {
        l.outage = Some(OutageState::disconnected());
        // 不关窗：等用户点「重新连接」或「关闭」
    }
}
```

### 8.2 不变量（写进代码注释 + review 检查）

1. `PlayerView` 进程内 ≤ 1 个；`InputState` 也只有一个。
2. `worker` 在同一时刻 ≤ 1 个；换源必须先置 `None`。
3. 视频区 bounds 只由 shell 计算；模式不得直接改 `right/left/width`。
4. 控制栏宽度与面板宽度解耦：面板 400 只覆盖，不缩控制栏。
5. 所有异步结果必须验代际；模式切换后旧代际一律丢弃。
6. 直播不写历史 / 续播；点播不建立 WebSocket。
7. `shell.rs` 不出现业务标识（`bvid` / `room_id` / `cid` / `aid`）。
8. `video/*` 与 `live/*` 不互相 `use`。
9. 新增模式只实现插槽，不改 widgets。
10. 面板 Tab 内容渲染只走 `panel_body(tab)` 分派，widget 不认识业务。

### B. 命名约定

| 前缀 | 含义 |
| --- | --- |
| `Player*` | 跨模式共享（PlayerView / PlayerModel / PlayerChrome） |
| `Video*` | 点播会话（VideoState / VideoAction） |
| `Live*` | 直播会话（LiveState / LiveChatState / LiveAction） |
| `*Spec` / `*Model` | 只读插槽数据，不含 `cx` |
| `*State` | 可变状态 |
| `*Generation` | 异步代际 |
